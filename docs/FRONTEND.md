# Frontend run and verification guide

The browser application is static HTML and vanilla JavaScript. It has no bundler and no third-party runtime dependency.

## Routes

- `/`: reception kiosk; requires a Cognito user in `kiosk` or `admin`.
- `/admin/`: HR administration; requires the `admin` Cognito group.
- `/callback.html`: Cognito authorization-code + PKCE callback.
- `/config.json`: generated by the access Terraform module; do not commit real environment values.

The access module uploads every file under `web/` to the private web bucket and generates `config.json` from the Cognito, raw-bucket and API resources. HTML and assets use no-cache headers so changes are visible without a CloudFront invalidation.

## Local browser verification against a deployed dev stack

1. Install Python 3.12 and clone the repository.
2. Create an untracked `web/config.json` with the deployed dev values:

```json
{
  "region": "ap-south-1",
  "userPoolId": "<dev Cognito user pool ID>",
  "clientId": "<dev public app client ID>",
  "cognitoDomain": "https://<dev Cognito domain>.auth.ap-south-1.amazoncognito.com",
  "apiBase": "https://<dev API Gateway endpoint>/api",
  "rawBucketUrl": "https://<dev raw bucket>.s3.ap-south-1.amazonaws.com"
}
```

3. Ensure the dev Cognito app client callback and logout URLs include `http://localhost:8000/callback.html` and `http://localhost:8000/`.
4. Ensure the dev raw-bucket CORS allowed origins include `http://localhost:8000`.
5. Run `python -m http.server 8000 --directory web` and open `http://localhost:8000`. Camera access is permitted on localhost.

For the deployed site, the generated config uses the same-origin API base `/api`. Do not point production users at a direct API Gateway URL.

## First deployment CORS step

The raw bucket is created by the foundation module, while the CloudFront distribution is created by the access module. To avoid a Terraform dependency cycle, the first deployment uses the configured `allowed_origins` list (default: localhost). After the first approved deployment, add the exact CloudFront site origin from the Terraform output to `allowed_origins`, `callback_urls` and `logout_urls`, then run a reviewed second plan/apply. This is required for browser-to-S3 presigned POST uploads and Cognito Hosted UI redirects to work on the deployed domain.

## Browser verification matrix

| Scenario | Expected result | Evidence |
|---|---|---|
| Kiosk user sign-in | PKCE callback returns to kiosk; camera permission requested | Record browser + result |
| Admin user opens kiosk | Allowed to scan | Record browser + result |
| Non-kiosk/non-admin opens kiosk | Access denied | Record browser + result |
| Admin sign-in | Redirects to `/admin/` | Record browser + result |
| Camera denied | Clear error and retry option | Record browser + result |
| No face / multiple faces / low quality | Contract result shown in kiosk | Record request ID + result code |
| Matched clock-in / clock-out / duplicate | Name, action and IST time shown | Record request ID + result code |
| Employee creation without consent | Browser blocks submit; API independently rejects it | Record result |
| Enrollment of 3–5 photos | Per-photo result shown; count refreshes | Record employee test ID only |
| Offboarding | Employee deactivated, face templates deleted, history retained | Record API result |
| Attendance filters and pagination | Correct rows and next page | Record filters |
| Daily / weekly report | JSON summary and CSV link when generated | Record period |
| Expired session / 401 | User is sent through sign-in again | Record result |
| Offline / API failure | Sanitized error; no raw token in UI or logs | Record result |
| Chrome desktop + Android | Required browser coverage | Device + version |
| Safari iOS | Test if device available; otherwise mark not tested | Device + version |

Do not use real employee biometrics in screenshots, logs, test fixtures or Git. Use consenting test participants and delete test data after the approved dev test.

## Deployed-stack API smoke test

After a reviewed dev deployment, use `scripts/e2e_smoke.sh` to create a consented test employee, enroll three local JPEGs, run at least 20 repeated scans, verify debounce and query attendance. See [scripts/README.md](../scripts/README.md) for required environment variables and cleanup behaviour. The script leaves attendance/audit history but deactivates the test employee and removes its indexed face templates. Its latency metric excludes browser capture/rendering, so it does not replace the browser/device N01 test.
